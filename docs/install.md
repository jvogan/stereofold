# Install Stereofold

Use this checkout's runtime and skills directly, or install a packaged plugin.
Claude Science supports a local command connector. The optional scripts in
`harness/kits/` install from this checkout and derive their paths automatically.

## Use the checkout directly

Clone the repository and open it in your agent. Its `AGENTS.md` and `CLAUDE.md`
point to the canonical setup, scene-control and presentation skills in
`plugin/skills/`. The full source workflow needs Node.js 22 or newer; committed
runtime bundles require no dependency installation or build.

Find the absolute Node executable with `command -v node`. Register the shipped
server using that executable and your checkout's absolute path:

```sh
codex mcp add stereo_structure -- \
  /absolute/path/to/node /absolute/path/to/stereofold/plugin/dist/server.mjs
```

For Claude Code:

```sh
claude mcp add stereo_structure --scope user -- \
  /absolute/path/to/node /absolute/path/to/stereofold/plugin/dist/server.mjs
```

Use the Codex profile used by your app or CLI. Preserve unrelated MCP entries,
and register only once: a packaged plugin can already provide this server.
Run Claude Code from the checkout root or another project, rather than from
`plugin/`, whose `.mcp.json` can offer a second project registration. Reload
the host connection or start a new conversation to expose the added tools.
Check `codex mcp list` or `claude mcp list` and the actual advertised tool names.

In this checkout, read the skill entrypoints directly. To use them in another
project, copy each needed complete folder from `plugin/skills/` into that
project's `.agents/skills/` for Codex or `.claude/skills/` for Claude Code.
Keep scripts, assets and references together, and preserve other skills.
Use the host's configured personal skill directory when preferred. Claude
Science supports skill upload or GitHub import and
[local command registration](#claude-science-local-mcp-server).

Copied setup scripts still need the runtime's location. Run
`node setup-check.mjs --root /absolute/path/to/stereofold/plugin --no-write`
from the copied setup skill's `scripts/` directory, or run the canonical
script in the checkout. From the checkout root, verify the runtime with:

```sh
node plugin/skills/stereofold-setup/scripts/open-check.mjs
```

The molecular-presentation skill can create and compile lesson files alone.
Desktop presentation uses the separately installed Molecular Structure Viewer;
headset presentation uses the full Stereofold runtime and stereo-structure
skill through the source registration above. The smaller portable lesson
package does not contain the headset runtime.

## Install from GitHub

The repository is a plugin marketplace named `stereofold`, and its plugin directory is `plugin/`. The runtime bundles in `plugin/dist/` are committed, so installing needs only Node.js 22 or newer: no pnpm, no Python, and no build.

For the Codex CLI and Codex desktop app, using the profile selected by your CLI:

```sh
codex plugin marketplace add https://github.com/jvogan/stereofold
codex plugin add stereofold@stereofold
```

If your shell has no `codex` command, install the Codex CLI first. Restart your Codex app if it was running, then start a fresh conversation.

For Claude Code, then start a new `claude` session:

```sh
claude plugin marketplace add jvogan/stereofold
claude plugin install stereofold@stereofold
```

For Claude Science, clone the repository and add its `plugin/dist/server.mjs` as a local command connector, as [Claude Science local MCP server](#claude-science-local-mcp-server) describes.

A share generated by `plugin/scripts/package-share.ts` is the second layout: its marketplace is `stereofold-local`, its plugin directory is `plugins/stereofold/`, and you install `stereofold@stereofold-local`. [Make and install a local share](#make-and-install-a-local-share) covers it.

### Import for a managed workspace

Where GitHub marketplace import is available, a ChatGPT workspace admin can
distribute the full plugin through **Admin > Plugins > Add > Import marketplace**:

- **Source:** `https://github.com/jvogan/stereofold`
- **Path:** leave empty; the marketplace is at the repository root.
- **Branch, tag, or commit:** `main` for updates, or a tested commit to pin it.

Review the import results and make Stereofold available to the intended members.
OpenAI marks imported plugins that declare MCP servers as **Desktop only**
for use in the ChatGPT desktop app.
Stereofold's server runs on each user's computer; the maintainer does not need
to host a shared MCP service. Members still need Node.js 22 or newer and their
requested device setup. Workspace permissions and GitHub access apply.

This workspace distribution route is separate from public directory review.
See OpenAI's [marketplace import guide](https://learn.chatgpt.com/docs/enterprise/plugin-management).

### Other MCP hosts

Another MCP host can run the same stdio server with an absolute Node path and the absolute path of `plugin/dist/server.mjs` in a clone. Use the host's browser or MCP Apps support to display the inspector. For Claude Desktop, add the server to the `mcpServers` object in `~/Library/Application Support/Claude/claude_desktop_config.json`, keep every existing entry, and restart Claude Desktop:

```json
{
  "mcpServers": {
    "stereofold": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/stereofold/plugin/dist/server.mjs"]
    }
  }
}
```

## Build from source

You need a build only to change the code or to make a share. Discover this checkout instead of assuming where another user put it:

```sh
git rev-parse --show-toplevel
cd /absolute/path/printed/by/the/command
```

Building needs Node.js 22.13 or newer, pnpm 11.19.0, and Python 3 on PATH; the
release gate runs `python3` for its guarded directory swap
(`plugin/scripts/release.ts`). Install the workspace dependencies first, then
build:

```sh
pnpm install --frozen-lockfile
pnpm --filter stereo-structure build
pnpm --filter stereo-structure smoke
pnpm --filter stereo-structure release
```

`build` and `smoke` are the development checks. The full release gate, with
the test suite, is in
[first run and Quest sharing](first-run-and-sharing.md#build-and-verify-a-release).

`release` stages `plugin/release/stereofold/`: it rebuilds, copies the staged
directory to a disposable operating-system temp directory, smoke-tests that
isolated copy with no `node_modules`, and removes the disposable copy. Package
that staged artifact into a share for another machine, as
[Make and install a local share](#make-and-install-a-local-share) describes; the
GitHub marketplace install uses the committed `plugin/` directory directly. See
[release.md](release.md) for the staged contents and guarantees.

## What reaches the network

Stereofold runs on your own machine, requires no Stereofold account, and sends no telemetry to a publisher-operated service. Local diagnostics help your agent troubleshoot rendering and input. These requests reach the network, and each reveals the machine's IP address and what was asked for to the host that answers it:

- A PDB ID given to `stereo_structure.inspect`, `stereo_structure.open`, or `stereo_structure.control` with `action: "load_pdb"` makes one HTTPS request to `https://files.rcsb.org/download/<PDB-ID>.cif`.
- An AlphaFold source fetches `/files/AF-<accession>-F1-model_v6.cif` from `alphafold.ebi.ac.uk`.
- A `url` source fetches the HTTPS address you give, then the host of each `https` redirect, up to five.
- Growing a lesson to a stage that is not cached fetches that stage's coordinate or map file from `files.rcsb.org`, or from `ftp.ebi.ac.uk` (EMDB) for the one stage that uses a density map, at the address in `plugin/demos/index.json`.

Putting a structure on the Quest can add two more:

- Meta Web Launch opens `https://www.oculus.com/open_url/` in this Mac's browser. Meta receives the page address, which is this Mac's private Wi-Fi address, and the one-time pairing code when the launch includes it. The code expires in ten minutes and works once.
- **Send using Meta** starts a `cloudflared` quick tunnel, and only when you choose it. The headset then loads the page and the structure from a `trycloudflare.com` address through Cloudflare's relay, and Meta receives that address. The link lasts 30 minutes. **Connect over Wi-Fi** uses no relay: the headset loads everything from this Mac over your network.

Speech from the headset controller is transcribed on this Mac: the Apple route requires on-device recognition, and Whisper runs locally. The in-headset **Talk** row uses a separate route that is off until you configure an OAuth helper (`oauthAuthHelper` in `~/.stereofold/config.json`, or `STEREOFOLD_OAUTH_AUTH_HELPER`). With that helper, each Talk recording, at most 12 seconds, goes to OpenAI's Realtime API (`api.openai.com`) for transcription. The `system` reply voice speaks through macOS `say`. The `oauth` reply voice, which the server uses when no provider is set, passes each reply's text to a separate `agent-voice` helper when one is installed, and that helper decides where the text goes. [Voice on a Mac](#voice-on-a-mac) covers both routes. For a public entry, the inspector's **Open Mol\* website** button opens `https://molstar.org/viewer/?pdb=<ID>`, so that site receives the PDB ID and no coordinates.

The server writes each PDB entry and AlphaFold model it fetches to `~/Library/Caches/Stereofold/sources/`, and each grown lesson stage to `~/Library/Caches/Stereofold/demos/`. Loading a public entry fetches it again rather than reading that cache. Spoken replies are cached as audio in `~/Library/Caches/Stereofold/reply-voice/` for up to seven days, at most 64 clips, under names that do not reveal the text. If you set `STEREOFOLD_PTT_TRANSCRIPTS`, controller transcripts are written to that file, and `STEREOFOLD_PTT_TEXT_COMMAND` runs the command you name on each transcript. The public-source cache excludes URL sources, local files, and pasted coordinates. Direct file loading with `inspect_file` reads coordinates locally; sharing sends the selected scene to paired devices, using the relay only when requested. Coordinates pasted into chat or tool inputs follow your agent host’s data policies. Screenshots, exports, and external helpers follow their respective destinations and policies. The viewer bundles its own assets, so it needs no content delivery network at runtime.

This section covers the MCP server that the hosts run. Installing from source contacts your package registry, and the optional developer scripts under `plugin/scripts/` make their own connections, such as the voice bridge to `api.anthropic.com` and the paid Live acceptance test to OpenAI.

## Voice on a Mac

Controller push-to-talk (hold **A** or **X**) transcribes on this Mac, not in the headset. On macOS the recognizer is Apple's on-device Speech framework, so a new user installs no whisper model. The in-headset **Talk** row is a separate route: its helper sends the captured audio to OpenAI Realtime and needs an OAuth auth module that Stereofold does not bundle, so a ready local transcriber does not make the **Talk** row ready.

No clone or share carries a compiled Apple helper; build it on the Mac that runs the host. From the repository root:

```sh
sh plugin/native/applespeech/build.sh
```

That compiles `plugin/native/applespeech/transcribe.swift` with `xcrun swiftc` into `plugin/native/applespeech/bin/applespeech`, a 91 KB binary linked only against system frameworks. It needs the Xcode command line tools (`xcode-select --install`). The host looks in its own plugin directory's `native/applespeech/bin/` before any Homebrew install. A Codex or Claude Code marketplace install runs from its own installed copy, so either run the same script inside that installed plugin directory or set `STEREOFOLD_APPLESPEECH_BIN` to the binary built here. Voice also needs `ffmpeg`, Speech Recognition consent in the application that launches the host, and a configured reply provider.

ffmpeg is still required. Quest Browser records WebM/Opus, which AVFoundation does not open, so ffmpeg decodes every clip to 16 kHz PCM before either recognizer runs.

The first press raises a macOS Speech Recognition dialog, and macOS raises it against the application that launched the host, Terminal or Claude Code. Click Allow there before the headset goes on. The grant belongs to that app rather than to Stereofold, so granting Terminal once grants nothing to a host you later start from Claude Code, and it is asked for once per app. A host started by launchd has no window to show the dialog in, so its presses would be refused; the Claude Science route stays on whisper for that reason. A press the recognizer refuses for any host-level reason, consent included, is transcribed by whisper instead and the transcript records why. On a Mac with no whisper install — the one the Apple route exists for — there is nothing to fall back to and the press is lost, so click the dialog first. The host says which of the two it is at startup.

Whisper remains the alternative and the route off macOS: `whisper-cli` from the `whisper-cpp` formula, plus a model at `~/.cache/whisper-cpp/ggml-base.en.bin` or any readable model named by `STEREOFOLD_WHISPER_MODEL`. The host picks whisper whenever the platform is not macOS or the Swift tool has not been built.

These variables configure transcription and transcript delivery:

| Variable | What it sets |
| --- | --- |
| `STEREOFOLD_PTT_TRANSCRIBE` | `1` turns push-to-talk transcription on; `0` turns it off. Unset enables it when a local transcriber is available. |
| `STEREOFOLD_PTT_TRANSCRIBER` | `apple` or `whisper`. Unset picks Apple on a Mac that has the tool built, whisper otherwise. |
| `STEREOFOLD_APPLESPEECH_BIN` | An absolute path to `applespeech`, for a binary kept outside the package. |
| `STEREOFOLD_WHISPER_BIN` | An absolute path to `whisper-cli`, including as the fallback for Apple. |
| `STEREOFOLD_WHISPER_MODEL` | An absolute path to the whisper model, including as the fallback for Apple. |
| `STEREOFOLD_FFMPEG_BIN` | An absolute path to `ffmpeg`, which decodes audio before either recognizer runs. |
| `STEREOFOLD_PTT_SILENCE_RMS` | The loudest-100 ms threshold below which a press counts as silence and no recognizer runs. Default `0.012`; `0` disables it. |
| `STEREOFOLD_PTT_TRANSCRIPTS` | An absolute file path to append transcript records as JSON lines. |
| `STEREOFOLD_PTT_TEXT_COMMAND` | A shell command run once per transcript, with the text on standard input. |
| `STEREOFOLD_BRIDGE_DIR` | An absolute directory path for transcript delivery to a running headset bridge. |

The host prints which route it chose at startup, and for Apple's, what the consent dialog looks like.

## Color and style

The stereo viewer's Settings drawer has a **Look** group with two choices that change how a loaded structure is drawn, without reloading it. **Colour** takes Chain, Rainbow N to C, Secondary structure, Element, or Confidence (pLDDT / B); **Style** takes Cartoon, Ball and stick, or Surface. The defaults are Chain and Cartoon. Changing **Colour** never moves the camera. Changing **Style** can change the size of the visible structure, and the viewer reframes when it does.

Confidence asks for Mol\*'s pLDDT theme and falls back to its B-factor theme on a structure Mol\* considers experimental, which is why the label names both. Anaglyph overrides the choice with a brightness-only theme for as long as it is on, then restores it.

The assistant can set both: `stereo_structure.open` takes optional `color` and `style`, and `stereo_structure.control` with the returned `sessionId` and `action: "set_look"` recolors or restyles what is already loaded. Neither reaches the network.

## Make and install a local share

A share is the second distribution layout: a fixed build that you copy to
another machine, which then installs it from a local directory. Its marketplace is `stereofold-local` and its
plugin directory is `plugins/stereofold/`. Codex needs the complete share, not
`plugin/release/stereofold/` by itself. After `release` succeeds, create the
share outside the checkout from the discovered repository root, then install it:

```sh
pnpm --filter stereo-structure exec tsx scripts/package-share.ts \
  --artifact release/stereofold \
  --out /absolute/path/to/stereofold-share
cd /absolute/path/to/stereofold-share
shasum -a 256 -c SHA256SUMS
codex plugin marketplace add /absolute/path/to/stereofold-share
codex plugin marketplace list --json
codex plugin add stereofold@stereofold-local
```

If only `stereofold-marketplace.tar.gz` was transferred, first run `mkdir
/absolute/path/to/stereofold-share` and `tar -xzf
/absolute/path/to/stereofold-marketplace.tar.gz -C
/absolute/path/to/stereofold-share`, then start the sequence above at `cd`.
The extracted root must contain `.agents/plugins/marketplace.json` beside
`plugins/stereofold/`. Add the share root as the marketplace, not its
`plugins/stereofold/` directory, and do not copy files into a Codex cache by
hand. Claude Code installs the same share with
`claude plugin marketplace add /absolute/path/to/stereofold-share` and
`claude plugin install stereofold@stereofold-local`.

Install the complete artifact to keep its five runtime assets together: `dist/server.mjs`,
`dist/viewer.html`, `dist/inspector.html`, `dist/inspector.css`, and `dist/inspector-host.js`.
The server and panels must come from the same build.

### Maintainer installer safety

The source installers in `harness/kits/` reject symlinked or non-regular configuration
targets and non-canonical parents before modifying host state. JSON changes
hold the parent by directory descriptor, use no-follow reads and temporary
files, serialize this helper's own writers with a sidecar advisory lock, compare
the target inode and bytes immediately before atomically replacing it, and fail
when that comparison detects a change. External editors do not honor the
helper's lock, and a portable atomic compare-and-replace primitive is not used,
so an unrelated writer could still race the final comparison-to-replace
window. Keep each host disconnected and do not edit the config while an
installer is running. Claude Science also receives a no-follow dated backup of
the exact config bytes that were parsed.

The descriptor-relative/no-follow checks prevent path redirection and detect
ordinary or cooperating concurrent changes. They are not a security boundary
against an actively malicious, noncooperating process running as the same user
and controlling the plugin or config parent directory; those parent directories
must remain trusted during installation.

The Codex plugin copy also snapshots and hashes the complete verified artifact
before copying, requires an identical source re-snapshot, and checks the staged
paths, modes, sizes, and hashes before its exclusive swap. If the artifact
changes during installation, the existing personal plugin stays in place.

## After a rebuild

Before trusting anything on screen, run the [live check](./host-verification.md#live-check-inside-a-host): fresh conversation, load 1CRN with `stereo_structure.open`, retain the returned `sessionId`, choose Parallel, call `stereo_structure.get_state` with that ID, and read `structuredContent.diagnostics`. Also open the focused inspector with `stereo_structure.inspect` and verify its own saved view mounts. The proof of which stereo-viewer bytes are mounted is `diagnostics.viewerBuild`, compared against the hash `pnpm --filter stereo-structure smoke` prints. The server registers the `stereo_structure.*` tools that `pnpm --filter stereo-structure smoke` asserts by name; read that list rather than a count typed here. At this checkout there are 64 registered tools: 37 model-visible tools (`continue_session`, `open_inspector`, `recall_headset`, `switch_assistant`, `undo_last_change`, `redo_last_change`, `inspect`, `inspect_file`, `inspect_scene`, `inspect_lesson`, `inspect_experience`, `list_experiences`, `navigate_experience`, `grow_structure`, `open_companion`, `manage_companion`, `control_tour`, `get_inspection_state`, `get_readiness`, `update_inspection`, `manage_inspection_view`, `emphasize`, `focus_selection`, `replace_inspection_source`, `open_detailed_view`, `import_detailed_view`, `say_to_headset`, `speak_to_headset`, `listen_voice`, `capture_headset_view`, `read_headset_browser`, `read_headset_log`, `open`, `control`, `get_state`, `set_mode`, `set_motion`) and 27 app-only hydration, synchronization, and lease tools. ## Claude Science local MCP server

Claude Science runs the MCP server as a local command connector. Clone the repository:

```sh
git clone https://github.com/jvogan/stereofold
cd stereofold
```

The clone's committed `plugin/dist/server.mjs` needs no build. In **Settings** > **Connectors**, choose **Add connector** > **Local command**. Use the absolute Node executable as the command and the absolute server path as its argument. Under **Advanced**, add environment variables for the features you use. Save the connector and start a fresh conversation. See Claude Science's [custom connector instructions](https://claude.com/docs/claude-science/custom-connectors).

The example below shows the corresponding entry for versions that use `~/.claude-science/mcp/local-mcp.json`. Replace every example path with its location on your machine. It names the absolute Node executable (`command -v node` prints it; the example uses Homebrew's) and the absolute server path. For a share, the server is `plugins/stereofold/dist/server.mjs` under the share root instead. The entry carries no credentials. Use absolute tool paths when the connector has a restricted `PATH`. Remove optional tool entries for tools you have not installed:

```json
{
  "name": "stereofold",
  "command": "/opt/homebrew/bin/node",
  "args": [
    "/absolute/path/to/stereofold/plugin/dist/server.mjs"
  ],
  "env": {
    "STEREOFOLD_CLOUDFLARED": "/opt/homebrew/bin/cloudflared",
    "STEREOFOLD_PTT_TRANSCRIBE": "1",
    "STEREOFOLD_PTT_TRANSCRIBER": "whisper",
    "STEREOFOLD_ADB_BIN": "/opt/homebrew/bin/adb",
    "STEREOFOLD_BRIDGE_DIR": "/absolute/path/to/stereofold-bridge",
    "STEREOFOLD_SCENE_SERVICE": "/absolute/path/to/home/.stereofold/scene-service.json",
    "STEREOFOLD_SCENE_SOCKET": "/absolute/path/to/home/.stereofold/scene-service.sock"
  }
}
```

If the connector's sandbox blocks loopback TCP, start a headset host in a Mac terminal: run `node plugin/dist/headset-host.mjs 4HHB` in the clone, adding `--vision-pro` for Safari on Vision Pro, and keep it running. The two `STEREOFOLD_SCENE_*` entries let this server join that host's scene; they must be the real home directory's absolute paths, and the sandbox needs read and Unix-socket access to that `~/.stereofold` folder. [Two hosts on one scene](../plugin/QUICKSTART.md#two-hosts-on-one-scene) has the sandbox settings. When no host is running, `continue_session` answers with the exact command for this installation.

`STEREOFOLD_ADB_BIN` also gives the assistant the headset browser's debugger, which `read_headset_browser` uses to report the page's XR session, tour state and console rather than inferring them from a picture. That route needs three things and says which one is missing: adb reachable, developer mode on the headset, and `adb forward tcp:9333 localabstract:chrome_devtools_remote` already run, with `STEREOFOLD_DEVTOOLS_PORT` naming a different port when 9333 is taken.

Configure only the features you need: `cloudflared` enables the optional relay, `adb` enables Quest device capture and debugging, and the bridge directory lets an assistant read transcripts and captures. A background connector that cannot show the Apple Speech Recognition consent dialog should use `whisper`. [`harness/kits/claude-science.md`](../harness/kits/claude-science.md) explains the environment settings. Its source installer builds and registers a staged release with discovered paths; [`claude-science-local-mcp.json`](../harness/kits/claude-science-local-mcp.json) is a copy/edit example for the committed server.

### Manual configuration for versions with a local MCP file

Use these steps when your version reads `~/.claude-science/mcp/local-mcp.json`:

1. Quit Claude Science. Its daemon reads this file only at startup.
2. Open `~/.claude-science/mcp/local-mcp.json` in an editor. Preserve the top-level object and all existing `servers` entries.
3. Copy the single object above into that existing `servers` array, separated from its neighbor with a comma when needed. Do not replace the whole file with the kit if other servers are configured.
4. Under **Customize** > **Permissions**, grant read access to the plugin directory named in `args` (`plugin/` in a clone, or `plugins/stereofold/` in a share) and, if you set `STEREOFOLD_BRIDGE_DIR`, to that directory. In `~/.claude-science/config.toml`, add the actual `.stereofold` folder to `[sandbox] user_read_paths` and `[sandbox.network] allow_unix_sockets`, preserving existing paths.
5. Restart Claude Science and reconnect `stereofold` in its connector settings. In a new conversation, ask for a structure. The agent calls `continue_session` to join a running headset host, or `inspect` to start a scene. If the embedded panel does not mount, open the inspector in a browser or use the terminal host.

To remove it, quit or disconnect Claude Science, delete only the `servers` array entry whose `name` is `stereofold`, preserving valid JSON and every other entry, then restart and reconnect.

`stereo_structure.open` declares the sole automatic native-file viewer binding for `ui://stereo-structure/viewer`; it accepts raw coordinates through `structureText`. The binding uses `opensMimeTypes`, `opensExtensions`, `contentParam`, `contentEncoding`, and `promptHint`, and omits `nameParam` because the strict `open` schema has no filename property. `stereo_structure.inspect` declares `ui://stereo-structure/inspector` for PDB IDs or pasted mmCIF, without an automatic file binding.

For a headset, verify the connected browser and a `rendered` command receipt. Embedded panel behavior depends on the host version. The Vision Pro Safari route has been exercised in the visionOS simulator; check actual rendering and input on the headset you use.

# Stereofold in Claude Science

Add a **Local command** connector in **Settings** > **Connectors** with the absolute Node executable and the absolute path to `plugin/dist/server.mjs`. Add needed environment variables under **Advanced**. See [installation](../../docs/install.md#claude-science-local-mcp-server) and the [Claude Science documentation](https://claude.com/docs/claude-science/custom-connectors).

The following procedure covers versions that read a local MCP configuration file. You can use the committed server or a staged release. To update a staged release, rebuild it and restart the connector.

## The maintainer script

`harness/kits/install-claude-science.sh` derives the repository from its own path and discovers Node on PATH. Run it after installing source dependencies. It first rejects an unexpected, symlinked, or
non-regular config path. It then builds and verifies the release artifact, runs
the full smoke check, writes a no-follow dated backup, and atomically replaces
the Claude Science local MCP file, including the `STEREOFOLD_CLOUDFLARED`
environment entry shown in step 3. Its helper serializes its own writers and checks the
target immediately before replacement. Other editors do not honor that
advisory lock, so keep Claude Science disconnected and do not edit this file
while the installer runs. Otherwise another writer could change the file
between the final comparison and the replacement.

## Install (once)

1. Quit Claude Science completely. Edit its config while it is not running.

2. Build and record the viewer build hash:

   ```sh
   cd /absolute/path/to/stereofold
   pnpm install --frozen-lockfile
   pnpm --filter stereo-structure release && pnpm --filter stereo-structure smoke
   ```

   This needs Node.js 22.13 or newer, pnpm 11.19.0 and Python 3. To skip the
   build, point `args` in step 3 at the committed
   `/absolute/path/to/stereofold/plugin/dist/server.mjs` instead, and grant the
   clone's `plugin` directory in step 6.

3. Open `~/.claude-science/mcp/local-mcp.json` and add this object to its `servers` array. For a fresh clone, use [`claude-science-local-mcp.json`](claude-science-local-mcp.json) instead; it points at the committed server.

   ```json
   {
     "name": "stereofold",
     "command": "/opt/homebrew/bin/node",
     "args": ["/absolute/path/to/stereofold/plugin/release/stereofold/dist/server.mjs"],
     "env": {
       "STEREOFOLD_CLOUDFLARED": "/opt/homebrew/bin/cloudflared",
       "STEREOFOLD_PTT_TRANSCRIBE": "1",
       "STEREOFOLD_PTT_TRANSCRIBER": "whisper",
       "STEREOFOLD_ADB_BIN": "/opt/homebrew/bin/adb",
       "STEREOFOLD_BRIDGE_DIR": "/absolute/path/to/stereofold-bridge",
       "STEREOFOLD_SCENE_SERVICE": "/absolute/path/to/home/.stereofold/scene-service.json",
       "STEREOFOLD_SCENE_SOCKET": "/absolute/path/to/home/.stereofold/scene-service.sock"
     }
   }
   ```

   The Claude Science daemon runs with a stripped `PATH` that does not include
   Homebrew, so `open_companion` with `connection: "https"` fails with an
   ENOENT error without this entry. LAN and loopback connections do not need
   it, but set it anyway so the Meta relay works if you use it later.

   `STEREOFOLD_PTT_TRANSCRIBE` turns headset voice into text on this Mac, which
   is what `listen_voice` reads. The server switches it on by itself
   whenever `whisper-cli`, a whisper model and `ffmpeg` are installed, so this
   entry only makes the choice explicit; set it to `0` to keep the microphone
   off. The server looks for the binaries at their Homebrew paths first, so
   this works under a daemon with a stripped `PATH`.

   `STEREOFOLD_PTT_TRANSCRIBER` is set to `whisper` here on purpose, and this
   host is the reason the setting exists. Left unset, the server picks Apple's
   on-device recognizer on any Mac where an `applespeech` binary is present,
   and the release artifact this daemon launches carries one whenever the
   binary was built before the release was staged. Apple's route needs a macOS
   Speech Recognition grant, raised as a dialog against whichever application
   started the host, and a daemon with no window of its own can never show that
   dialog. Without this entry, every press spends a refused `applespeech` run
   before it falls back to whisper. Naming whisper skips the round trip. Use
   `apple` here only after granting Speech Recognition to Claude Science by
   some other route; there is no way to grant it from inside the headset.

   `STEREOFOLD_ADB_BIN` gives `capture_headset_view` its device route on this
   host. The tool first asks the immersive companion page for an image, which
   needs no adb. When the page cannot answer, it falls back to reading the
   headset's composited display over adb, and the daemon's stripped `PATH` has
   no Homebrew, so an adb that Claude Code and Codex both find is invisible
   here. Without this entry the fallback reports "No adb was found" on a Mac
   that has it. Point it at wherever platform-tools
   put `adb`; omit it if this Mac has none.

   `STEREOFOLD_BRIDGE_DIR` is where the server writes what the wearer said and
   saw, as small JSON files this host can read directly. Without it the
   transcript of live speech never leaves the server's memory. The directory is
   created at `0700` on demand, is gitignored, and holds no tokens: every
   capability-shaped key and value is stripped before a file is written. The
   sandbox still needs read access to it; step 6 grants that.

4. Relaunch Claude Science. The daemon reads `local-mcp.json` only at startup;
   a daemon that was already running before you wrote this entry has never
   attempted the connection. Saving the file is not enough.

5. Open Customize -> Connectors and reconnect `stereofold`. Expect it to report
   connected with no authentication prompt.

6. Grant the sandbox read access to the paths the route needs. Open
   `~/.claude-science/config.toml` and confirm `[sandbox] user_read_paths`
   holds each of these, adding whichever is missing:

   ```
   /absolute/path/to/stereofold/plugin/release/stereofold
   /absolute/path/to/stereofold-bridge
   /absolute/path/to/home/.stereofold
   ```

   The first is the server the daemon launches. The second is where the server
   writes what the wearer said and saw; without it those files are written and
   never read, and no headset speech reaches the assistant. Add the third path
   to `[sandbox.network] allow_unix_sockets` as well, so `continue_session`
   can connect to the Mac terminal's scene socket. The repo root is
   not granted and does not need to be. Editing this file needs another
   relaunch of Claude Science before the grant applies, so do it before the
   first session rather than after a failure. Nothing in this repo can write
   this file.

7. Start a NEW conversation (an existing one predates the connector) and run
   the checklist in the next section.

## Verify (condensed)

1. Ask what Stereofold tools are available. Expect the model-visible
   tools listed in [The real tool list](#the-real-tool-list) and none of the
   app-only ones.
2. Ask to open the `three-depth-markers` fixture. Expect a rendered 3D canvas
   from `ui://stereo-structure/viewer`, no network request.
3. Ask to inspect PDB `1CRN`. Expect a cartoon rendering from
   `ui://stereo-structure/inspector` with representation, color, background,
   opacity, labels, and clipping controls.
4. Rotate and re-color the molecule, save it in the panel, then call
   `get_inspection_state`. Expect `serverEpoch`, `sourceToken`,
   `stateRevision`, and `inspectionRevision` in the result.
5. If the connector sandbox blocks loopback TCP, its server cannot open the
   headset share. In a Mac terminal, from the clone, run
   `node plugin/dist/headset-host.mjs 1CRN` (add `--vision-pro` for Safari on
   Vision Pro) and leave it running. It prints the `https://<private-IPv4>:8443/`
   address, a one-time pairing code, a certificate fingerprint and an expiry,
   then `scene relay · ~/.stereofold/scene-service.sock`.
6. Put the headset on: press **Open** on the Meta page the host opened for a
   Quest, or paste the clipboard link into Safari on Vision Pro. Accept the
   certificate warning and tap Enter VR. Expect the molecule in the headset.
7. Ask Claude Science to join the Stereofold scene on this Mac and color it by
   chain. Expect `continue_session` to answer `role: "attached"`, and the
   change to draw in the headset with a rendered receipt. `manage_companion`
   with `action: "status"` lists the paired headset as a client.

Stop at the first failure and report what the panel or tool result shows.
Steps 1 through 7 completing cleanly is the pass condition; a Cloudflare relay
run and a dropped-file smoke test are optional.

## The real tool list

The plugin has 68 registered tools: 41 model-visible `stereo_structure.*` tools
and 27 app-only tools, counted from `plugin/scripts/tool-inventory.ts`.
`pnpm --filter stereo-structure smoke` asserts those lists by name; check that
output rather than this count. The app-only tools
are marked app-only (`_meta.ui.visibility = ['app']`) and must never appear in
a model-visible tool list; if one does, the host is ignoring that marking and
every private capability is exposed — stop and report it.

**Guided experiences and headset voice:**

| Tool | Mounts |
| --- | --- |
| `inspect_experience` | `ui://stereo-structure/inspector` |
| `list_experiences` | nothing (reads the bundled catalog) |
| `navigate_experience` | nothing (steps an already-open experience) |
| `listen_voice` | nothing (waits for the headset wearer to speak) |
| `say_to_headset` | nothing (captions and speaks a short reply in the headset) |
| `speak_to_headset` | nothing (queues a spoken reply for the wearer) |
| `recall_headset` | nothing (sends the headset tab back from the full Mol\* viewer to the companion page) |
| `switch_assistant` | nothing (hands the wearer's speech to another attached assistant, or reads who holds it) |

Answer the wearer with `say_to_headset`. Pass `{"text": "..."}`, 1 to 1,200
characters and at most 200 words, optionally `speak: false` for a caption only
and `holdSeconds` (2-15, default 6). A reply over either limit is refused; a long
reply within the limits is spoken as consecutive segments without truncation. The text is drawn on the
reply card below the wearer's gaze, separate from the structure and chapter
captions, and the sound
comes from the Mac, not the headset browser: Quest Browser has no
speech-synthesis voice, so the Mac renders the sentence, encodes it to Opus and
sends the clip inline with the caption. The reply needs nothing from this host.

`STEREOFOLD_REPLY_VOICE_PROVIDER` selects what renders the sentence. Unset means `oauth`,
which runs the `agent-voice` helper at
`~/.local/bin/agent-voice`, or wherever
`STEREOFOLD_AGENT_VOICE_BIN` names. A daemon that cannot reach that helper
returns the caption with `audible: false`. Add
`"STEREOFOLD_REPLY_VOICE_PROVIDER": "system"` to the server's `env` block in
step 3 to render replies with `/usr/bin/say` instead and keep the sentence on
this Mac.

`delivered: true` means a connected companion page took the caption;
`delivered: false` means no page had taken it yet, not that it was refused.
`audible: true` means a clip was rendered and sent with it. Neither field says
the wearer heard anything. `speak_to_headset` queues a short spoken line for
one bound companion panel through the same configured provider; prefer
`say_to_headset` for replies.

**Legacy stereo viewer** — kept for compatibility, not where new work happens:

| Tool | Mounts |
| --- | --- |
| `open` | `ui://stereo-structure/viewer`, and is the sole automatic native-file binding (`operon.dev/viewer`, `.pdb`/`.ent`/`.cif`/`.mmcif`) |
| `control` | nothing |
| `get_state` | nothing |
| `set_mode` | nothing |
| `set_motion` | nothing |

Because `open` owns the file binding, dropping a `.cif` file into Claude
Science opens the legacy stereo viewer, not the rich inspector. Use
`inspect_file` directly for real work; see the recommended path in
[Known limits in this host](#known-limits-in-this-host).

The `structure.*` namespace belongs to the separately installed Molecular
Structure Viewer plugin in Codex, not to this host. In Claude Science the
neighbors are the built-in 3Dmol previewer and the bundled
`ketcher-chemistry` server; hand either one's exported coordinate file to
`inspect_file` when the question needs stereo depth or a headset.

## Known limits in this host

One thing does not work in Claude Science, and no workaround inside the panel
fixes it:

- `app.openLink()` is not implemented by the Claude Science daemon, and the
  panel's inner iframe has no `allow-popups`. The desktop panel's "Open
  companion" button and the "Continue to Meta" link both do nothing when
  clicked here.

Two routes work around it, because the server prints the text or opens the
address itself:

- The private-Wi-Fi (LAN) route still works, because its address, pairing
  code, and certificate fingerprint render as plain selectable text rather
  than requiring a link click.
- You do not have to paste the full Mol* viewer's address by hand. Call
  `open_detailed_view` with `open: true` and the server opens its own loopback
  address in the Mac's default browser, through the same absolute
  `/usr/bin/open`. The address is still printed, so if the open fails you can
  paste it yourself, and the result says which happened.

For a headset, start `node plugin/dist/headset-host.mjs 4HHB` from the clone
root in a Mac terminal; add `--vision-pro` for Vision Pro. Pair the headset as
the terminal directs, then ask Claude Science to join the Stereofold scene on
this Mac and change it with `continue_session`. Keep the terminal and browser
tab open. See [the README](../../README.md#claude-science) for the sequence.

The terminal host handles the share outside the sandbox. `manage_companion`
with `action: "launch"` and `launch: "web"` repeats the launch for a companion
that is already open.
`STEREOFOLD_OPENER` replaces `/usr/bin/open` with any absolute path;
`plugin/scripts/claude-science-browser.ts` sets it to a recorder so scenarios
S6 and S7 read the exact links without opening a browser.

The Claude Science assistant's own sandbox has no network access at all, not
even loopback in the tested sandbox configuration. Current versions may offer different permissions; use the host's supported settings. It can only confirm a render
happened through tool results and through files inside its granted read
paths. The `STEREOFOLD_BRIDGE_DIR` entry in step 3 is that file bridge.

## Update after a code change

Run step 2 again, then quit and relaunch Claude Science, then reconnect
`stereofold` under Customize -> Connectors. Nothing else.

## Uninstall

Delete the `stereofold` object from the `servers` array and relaunch Claude Science.
